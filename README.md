## About Xenode Labs

Xenode Labs is home to Xenode's experimental web applications, AI projects, and technical explorations.

Where the [main Xenode repo](https://github.com/xenode-in/xenode) is focused on shipping a production privacy-first cloud platform, Labs is the sandbox — a space to prototype ideas, test new technical approaches, and explore concepts that may or may not ever become part of the core product.

Every project here is open source and built to experiment, learn, and push ideas forward.

---

## Philosophy

Labs follows a simpler set of rules than the main product:

- **Ship fast, iterate faster.** Projects here favor speed of learning over production polish.
- **Open by default.** Every experiment is public, warts and all.
- **No permanence guarantee.** Projects may be abandoned, merged into Xenode proper, or spun out as their own repos.
- **Privacy-minded, not always privacy-first.** Unlike the main platform, Labs projects may trade off some privacy guarantees in favor of exploring an idea quickly — this is always called out per-project.

---

## What's Inside

Labs projects generally fall into a few categories:

- **Web applications** — small, self-contained apps built to test an idea or UX pattern
- **AI / ML projects** — model experiments, prediction systems, local-AI prototypes
- **Technical explorations** — protocol research, infrastructure experiments, proof-of-concepts that inform decisions made in the main Xenode platform
- **Tools & scripts** — internal tooling that may be useful outside Xenode too

## Open Source Philosophy

Open source is at the heart of everything Xenode builds, and Labs is no exception.

Experiments here are public so anyone can inspect the approach, learn from what worked (or didn't), fork an idea, or contribute improvements. Community feedback, discussions, and contributions are welcome on every project, regardless of how early-stage it is.

## Looking for Contributors

Labs is a great place to get involved if you want to work on something smaller in scope than the main platform, or if you'd like to prototype your own idea within the Xenode ecosystem.

Whether you are a:

- Frontend developer
- Backend developer
- ML/AI engineer
- DevOps engineer
- Security researcher
- UI/UX designer
- Documentation writer

Your contributions are welcome — either on an existing experiment or a new one.

---

## Contributing

Since this repo is just an index, contributing an experiment means two steps:

1. Build your project in its own repository (under the `xenode-in` org or your own, your call).
2. Open a PR here adding a row to the project table above — name, category, status, and a link to the repo.

```bash
git checkout -b add/your-project
git commit -m "docs: add your-project to the index"
git push origin add/your-project
```

Make sure your project's own repo has a README covering what it does, its current status, and any known limitations.
